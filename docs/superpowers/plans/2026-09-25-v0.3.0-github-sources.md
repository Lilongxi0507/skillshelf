# SkillShelf v0.3.0 GitHub 固定来源实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (推荐) 或 `executing-plans` 逐任务实施本计划。每项任务都要以 checkbox 跟踪；修改共享符号前必须先做 GitNexus impact，测试先红后绿。

**Goal:** 将 83 项技能迁移到可验证的 GitHub 固定 commit 获取模型，保留 0.2.x npm legacy 兼容，完成生命周期/锁/离线/执行授权/跨平台验证，并发布可真实安装的 SkillShelf v0.3.0。

**Architecture:** 在现有安装事务和内容寻址 store 之前增加一个深的 acquisition Module：GitHub fixed-commit Adapter、legacy npm Adapter、显式 local fixture Adapter 统一返回已验证的内容对象和获取收据。新目录使用 schema 3 的 acquisition/provenance/manifest 身份；旧 schema 1/2 与 npm `Release` 继续走专用兼容路径。GitHub 压缩包只作为传输载体，固定来源清单、路径映射、overlay、treeDigest 和执行授权 receipt 才是内容身份。

**Tech Stack:** Node.js >=22.20.0、TypeScript strict ES modules、Node fetch/Web Streams、现有 YAML/Zod/tar/Commander、Node test runner、Python 3.10+ 第一方运行工具、GitHub Actions、npm OIDC。

**Spec:** `docs/superpowers/specs/2026-09-25-v0.3.0-github-sources-design.md`

## Global Constraints

- 新目录的 83 项技能和 8 个逻辑包默认使用 GitHub 固定 40 位 commit；不追踪 branch/tag/main，不接受任意 URL/镜像。
- npm 只发布 CLI 和 metadata-only catalog；已有 0.2.x 技能 npm 包不删除、不重打、不伪装为 GitHub 来源。
- 旧 schema 1/2、旧 npm exact artifact、旧项目锁和旧 bundle 必须保持可读/可恢复；加载旧数据不得隐式迁移或改写。
- 获取完成前不得提交 store/state/Agent 投影；网络错误、归档错误、hash/mode/许可证错误均 fail closed 并保留旧选择。
- GitHub archive 的 gzip/tar 字节不是内容身份；必须校验受审 catalog manifest 的完整 selected 文件集合、大小、SHA-256、Git mode、映射和 overlay。
- 禁止跟随选中树内的 symlink/hardlink/device/FIFO；拒绝路径穿越、重复/大小写/Unicode 歧义、gitlink、LFS pointer、submodule 和超限归档；不执行上游脚本、hooks 或依赖安装。
- `origin: github` 不能授予第一方 `run` 权限；第一方执行必须匹配可信目录、commit、tree/release digest、entrypoint、runtime 和独立 authorization receipt。
- 更新必须是目录审核后的新 packRevision；`check` 只读，`catalog refresh` 不更新技能，`update` 只更新当前范围未 pin 项；冻结项目不漂移。
- bundle 不得包含 Key、Provider 配置、生成物、用户绝对 Agent 路径、Node/CLI；可带已验证 selected 内容、manifest 和收据，不可凭自述产生信任。
- 所有重构/构建/大规模测试使用隔离资源；不修改 `/srv/panel` 生产代码，不触碰真实 SkillShelf home/Agent roots，不提交凭据。
- 共享函数在编辑前使用 GitNexus impact；HIGH/CRITICAL 风险必须记录并增加覆盖。提交前 `detect_changes(scope=all)` 必须非 partial/truncated。

## Review Focus

- 第一方改造快照与原始上游归属不能混淆；`clients/skills/panel-*` 不能成为公共下载路径。
- Taste basename 映射、Matt/Superpowers/GitNexus 多目录、Archify `THIRD_PARTY_NOTICES`、GitNexus required NOTICE、根 LICENSE overlays 不能静默丢失/覆盖。
- 同一 repo+commit 的归档只下载/解码一次；selected 内容体积和完整仓库传输体积分别显示。
- source migration、旧 npm history、frozen lock、bundle import、runtime authorization 必须互不越权。
- 版本、目录 revision、packRevision、treeDigest、archive receipt 和 CLI min version 不得继续全局伪装成同一个 SemVer。

## Expected Implementation Order

1. Phase 0–1（来源清单/身份/schema）
2. Phase 2（GitHub Adapter + archive security）
3. Phase 3（catalog/plan/release）

## Execution Recommendation

这是跨越数据模型、获取安全、事务生命周期、跨平台和发布流程的高风险架构变更；建议使用 `subagent-driven-development`，每个 phase/模块由独立任务实现，父会话在每个共享接口处做 impact、测试和合并审查。若不使用子代理，则用 `executing-plans` 按本计划逐项执行，不能把整个计划作为一次大改动。
